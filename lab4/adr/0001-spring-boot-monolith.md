# ADR-0001: Монолит на Spring Boot

## Контекст и постановка задачи

Как выбрать простой серверный каркас для учебного приложения, сохранив возможность тестирования API?

## Драйверы решения

- Один исполнитель и ограниченный срок
- Java уже определён в SRS
- REQ-MAINT-001, REQ-COST-001

## Рассмотренные варианты

- Spring Boot монолит
- Микросервисы
- Чистый Java HTTP-сервер

## Итог решения

Выбран вариант **«Spring Boot монолит»**, поскольку даёт готовые REST API, DI, валидацию и минимальные накладные расходы.

### Последствия

- Хорошо: единый процесс и простая сборка.
- Ограничение: при росте нагрузки масштабирование компонентов отдельно невозможно.

### Подтверждение

Проверить проектное решение в код-ревью и интеграционных тестах; результаты фиксировать в Pull Request.

## Плюсы и минусы вариантов

### Spring Boot монолит

- Плюс: малое время реализации и совместимость с текущим SRS.
- Минус: есть ограничения, перечисленные в последствиях решения.

### Микросервисы

- Плюс: реалистичная альтернативная архитектура.
- Минус: высокая дополнительная стоимость разработки и сопровождения для учебного проекта.

### Чистый Java HTTP-сервер

- Плюс: реалистичная альтернативная архитектура.
- Минус: высокая дополнительная стоимость разработки и сопровождения для учебного проекта.
