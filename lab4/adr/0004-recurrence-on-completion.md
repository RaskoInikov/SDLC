# ADR-0004: Повторение задачи при завершении

## Контекст и постановка задачи

Как добавить регулярные задачи без планировщика и не создавать дубли?

## Драйверы решения

- REQ-FUNC-013
- Фиксированная дата релиза
- REQ-REL-001

## Рассмотренные варианты

- Создание следующей задачи при DONE
- Фоновый планировщик
- Серия заранее созданных задач

## Итог решения

Выбран вариант **«Создание следующей задачи при DONE»**, поскольку сокращает объём разработки и позволяет создать ровно одну следующую задачу в транзакции.

### Последствия

- Хорошо: без фоновых процессов.
- Ограничение: новая задача появляется только после завершения текущей.

### Подтверждение

Проверить проектное решение в код-ревью и интеграционных тестах; результаты фиксировать в Pull Request.

## Плюсы и минусы вариантов

### Создание следующей задачи при DONE

- Плюс: малое время реализации и совместимость с текущим SRS.
- Минус: есть ограничения, перечисленные в последствиях решения.

### Фоновый планировщик

- Плюс: реалистичная альтернативная архитектура.
- Минус: высокая дополнительная стоимость разработки и сопровождения для учебного проекта.

### Серия заранее созданных задач

- Плюс: реалистичная альтернативная архитектура.
- Минус: высокая дополнительная стоимость разработки и сопровождения для учебного проекта.
