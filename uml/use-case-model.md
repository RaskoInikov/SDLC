# Модель вариантов использования TaskFlow

## Актёры

| Актёр | Роль |
|---|---|
| Пользователь | Основной актёр, работающий с задачами через браузер; отдельных ролей в релизе 1.0 нет. |

## Прецеденты

### UC-01 — Просмотреть Kanban-доску

**Актёр:** Пользователь (для UC-11 — включаемое системой действие). **Описание:** Пользователь открывает доску и видит задачи в трёх колонках.

**Предусловия:** Приложение открыто; доступно хранилище.

**Основной поток:**
1. Пользователь открывает главную страницу.
2. Интерфейс запрашивает GET /api/tasks.
3. Сервер читает задачи и возвращает JSON.
4. Интерфейс размещает каждую задачу в колонке по статусу.

**Альтернативы и ошибки:** А1: задач нет — показаны пустые колонки. Е1: хранилище недоступно — контролируемая ошибка.

**Постусловия:** Состояния задач не изменены.

**Требования SRS:** REQ-FUNC-002, REQ-FUNC-010.

### UC-02 — Создать задачу

**Актёр:** Пользователь (для UC-11 — включаемое системой действие). **Описание:** Добавление задачи с необязательными описанием и сроком.

**Предусловия:** Доска открыта.

**Основной поток:**
1. Пользователь выбирает «Новая задача».
2. Система показывает форму.
3. Пользователь вводит название, описание, приоритет и срок.
4. Система проверяет данные.
5. Сервер сохраняет задачу со статусом TODO.
6. Интерфейс показывает карточку в колонке «К выполнению».

**Альтернативы и ошибки:** А1: название пустое — показать ошибку, остаться в форме. А2: отмена — закрыть форму без сохранения. Е1: ошибка БД — операция не показана успешной.

**Постусловия:** Создана и сохранена одна задача.

**Требования SRS:** REQ-FUNC-001, REQ-FUNC-009, REQ-FUNC-010.

### UC-03 — Изменить задачу

**Актёр:** Пользователь (для UC-11 — включаемое системой действие). **Описание:** Корректировка названия, описания, приоритета и срока.

**Предусловия:** Выбрана существующая задача.

**Основной поток:**
1. Пользователь открывает редактирование.
2. Система показывает текущие значения.
3. Пользователь изменяет поля и нажимает «Сохранить».
4. Сервер проверяет поля и обновляет запись.
5. Карточка показывает новые значения.

**Альтернативы и ошибки:** А1: данные невалидны — показать сообщение у поля. Е1: задача удалена или БД недоступна — ошибка без ложного подтверждения.

**Постусловия:** Изменения устойчиво сохранены.

**Требования SRS:** REQ-FUNC-003, REQ-FUNC-006, REQ-FUNC-009.

### UC-04 — Изменить статус

**Актёр:** Пользователь (для UC-11 — включаемое системой действие). **Описание:** Перемещение задачи между колонками.

**Предусловия:** Задача существует.

**Основной поток:**
1. Пользователь выбирает новый статус.
2. Клиент направляет PATCH /api/tasks/{id}/status.
3. Сервис проверяет допустимость статуса и сохраняет изменение.
4. Карточка отображается в выбранной колонке.

**Альтернативы и ошибки:** А1: статус не изменился — изменений нет. А2: выбран DONE для повторяющейся задачи — UC-09. Е1: сбой сохранения — карточка остаётся в прежней колонке.

**Постусловия:** Новый статус сохраняется после перезагрузки.

**Требования SRS:** REQ-FUNC-004, REQ-FUNC-013.

### UC-05 — Удалить задачу

**Актёр:** Пользователь (для UC-11 — включаемое системой действие). **Описание:** Удаление записи только после подтверждения.

**Предусловия:** Задача существует.

**Основной поток:**
1. Пользователь нажимает «Удалить».
2. Система запрашивает подтверждение.
3. Пользователь подтверждает.
4. Сервер выполняет DELETE /api/tasks/{id}.
5. Карточка исчезает с доски.

**Альтернативы и ошибки:** А1: пользователь отменяет — запись сохраняется. Е1: ошибка БД — карточка не скрывается как удалённая.

**Постусловия:** Задача отсутствует в хранилище.

**Требования SRS:** REQ-FUNC-005, REQ-REL-001.

### UC-06 — Найти задачи

**Актёр:** Пользователь (для UC-11 — включаемое системой действие). **Описание:** Поиск по названию и описанию.

**Предусловия:** Доска открыта.

**Основной поток:**
1. Пользователь вводит запрос.
2. Система сравнивает запрос с названием и описанием задач.
3. На доске показаны совпадения.

**Альтернативы и ошибки:** А1: совпадений нет — сообщение об отсутствии результатов.

**Постусловия:** Задачи не изменены.

**Требования SRS:** REQ-FUNC-007.

### UC-07 — Отфильтровать задачи

**Актёр:** Пользователь (для UC-11 — включаемое системой действие). **Описание:** Отбор по статусу и приоритету.

**Предусловия:** Доска открыта.

**Основной поток:**
1. Пользователь выбирает фильтры.
2. Система применяет условия статуса и приоритета.
3. Доска показывает подходящие карточки.

**Альтернативы и ошибки:** А1: нет совпадений — пустой результат; сброс фильтров возвращает полный список.

**Постусловия:** Данные не изменены.

**Требования SRS:** REQ-FUNC-008.

### UC-08 — Экспортировать CSV

**Актёр:** Пользователь (для UC-11 — включаемое системой действие). **Описание:** Выгрузка текущих сохранённых задач в UTF-8 CSV.

**Предусловия:** Хранилище доступно.

**Основной поток:**
1. Пользователь выбирает «Экспорт CSV».
2. Сервер получает сохранённые задачи.
3. Экспортёр формирует заголовок id,title,description,priority,status,dueDate.
4. Поля с кавычками и запятыми экранируются по правилам CSV.
5. Браузер загружает файл.

**Альтернативы и ошибки:** А1: список пуст — файл содержит заголовок. Е1: ошибка чтения — система показывает ошибку экспорта.

**Постусловия:** Скачан CSV; данные в БД не изменены.

**Требования SRS:** REQ-FUNC-011.

### UC-09 — Создать следующий повтор

**Актёр:** Пользователь (для UC-11 — включаемое системой действие). **Описание:** При завершении периодической задачи появляется ровно один следующий экземпляр.

**Предусловия:** Задача имеет DAILY либо WEEKLY и dueDate; статус ещё не DONE.

**Основной поток:**
1. Пользователь завершает задачу посредством UC-04.
2. Сервис атомарно изменяет текущий статус на DONE.
3. Сервис проверяет правило DAILY/WEEKLY и отсутствие уже созданного повтора.
4. Новый экземпляр получает исходные название, описание, приоритет и дату +1/+7 дней.
5. Сервис сохраняет новый экземпляр со статусом TODO.
6. Доска отображает завершённую и новую задачи.

**Альтернативы и ошибки:** А1: NONE — повтор не создаётся. А2: повторный запрос завершения — новый экземпляр не создаётся. Е1: сбой транзакции — статус/повтор не фиксируются частично.

**Постусловия:** Ровно один следующий экземпляр для каждого завершения.

**Требования SRS:** REQ-FUNC-013, REQ-REL-001.

### UC-10 — Назначить повторение

**Актёр:** Пользователь (для UC-11 — включаемое системой действие). **Описание:** Выбор NONE/DAILY/WEEKLY при создании или редактировании.

**Предусловия:** Открыта форма задачи.

**Основной поток:**
1. Пользователь выбирает правило повтора.
2. Система проверяет наличие даты при DAILY/WEEKLY.
3. Сервис сохраняет правило вместе с задачей.

**Альтернативы и ошибки:** А1: нет dueDate — периодическое правило недоступно, показана ошибка.

**Постусловия:** У задачи сохранено допустимое правило повторения.

**Требования SRS:** REQ-FUNC-013.

### UC-11 — Проверить ввод

**Актёр:** Пользователь (для UC-11 — включаемое системой действие). **Описание:** Общее обязательное серверное действие для записи задачи.

**Предусловия:** Получен запрос на создание/обновление.

**Основной поток:**
1. Сервис проверяет обязательное непустое название.
2. Проверяются допустимые значения статуса, приоритета и правила повторения.
3. При корректных данных разрешается запись.

**Альтернативы и ошибки:** А1: ошибка валидации — HTTP 4xx и безопасное сообщение; в БД ничего не меняется.

**Постусловия:** Некорректные данные не сохранены.

**Требования SRS:** REQ-FUNC-009, REQ-SEC-001.

## Связи

UC-02 и UC-03 включают UC-11 (валидация); UC-10 расширяет UC-02/UC-03 при выборе повторения; UC-09 расширяет UC-04 при переходе периодической задачи в DONE. UC-09 является системным продолжением UC-04, а не самостоятельным действием пользователя.
