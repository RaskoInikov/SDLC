# ADR-0002: UML-модель статической структуры TaskFlow

**Статус:** принято для проектной документации ЛР6; требует синхронизации с реализацией.

## Контекст
ADR-0001 и SDD ЛР5 задают динамическую модель Java-монолита. Нужно показать классы, компоненты, их интерфейсы, порты, развёртывание и связь представлений. Исходный код и точное окружение не предоставлены.

## Решение
Применить UML 2.5; хранить источники PlantUML и draw.io в `uml/models`, изображения PNG и SVG в `uml/images`. Диаграмму классов строить от сущности Task, компонентов SDD и сообщений последовательностей создания/завершения. Типы и сигнатуры — проектные. Интерфейс TaskRepository отделяет бизнес-логику от способа хранения; PersistentTaskRepository реализует его. Атрибуты закрыты, публичные операции формируют контракт. Вспомогательные generateNext и escape закрыты. Не вводить наследование, композицию или агрегацию без основания.

## Механизмы построения и связи
1. **Классы:** атрибуты выводятся из SRS/SDD, операции — из UC и событий состояний. Сплошная стрелка показывает навигацию ассоциации; пунктирная — зависимость; пунктир с пустым треугольником — реализацию. Кратность 0..1 обозначает необязательного предшественника задачи.
2. **Компоненты:** от логических компонентов SDD. Предоставляемый интерфейс изображается шаром, требуемый — гнездом. Сборочный соединитель связывает потребителя и поставщика контракта. Порты HTTP и Storage показаны квадратами на границе подсистемы; делегирование связывает их с контроллером и репозиторием соответственно. Интерфейсы на компонентной диаграмме не обязаны быть отдельными Java interface.
3. **Развёртывание:** от монолитной архитектуры. Устройство пользователя содержит браузер; сервер содержит JVM и постоянное хранилище. JAR включает классы и библиотеки, конфигурация представлена условным application.yml. Манифестация связывает JAR с подсистемой API; пути связи показывают HTTP и доступ к хранилищу. Web UI — статические ресурсы, доставляемые браузеру. Тип СУБД и порт не фиксируются без исходных данных.
4. **Связь представлений:** web::TaskController → TaskController; task::TaskService/Task/TaskInput → TaskService; TaskValidator → TaskValidator; persistence::TaskRepository/PersistentTaskRepository → TaskRepository; export::CsvExporter → CsvExporter. Эти компоненты развёртываются одним JAR, а не отдельными процессами.

## Защита от дублей повторов
Дополнить Task полями previousTaskId и recurrenceGenerated. Маркер на исходной задаче сохраняется после удаления следующего экземпляра и при повторном открытии задачи. В одной транзакции проверить старый статус, правило и маркер, изменить статус, создать следующий экземпляр и установить маркер. Блокировка или оптимистическая версия исходной записи вместе с уникальностью непустого previousTaskId исключают конкурентную генерацию. При ошибке откатываются все изменения. Это проектное решение, которое необходимо подтвердить интеграционными тестами.

## Альтернативы
Микросервисы отклонены: SDD ЛР5 задаёт монолит. Планировщик для повтора отклонён: повтор запускается при завершении, а не по времени. Фиксировать конкретную СУБД без проекта нецелесообразно.

## Последствия
Модель уточняет границы ответственности и единицу развёртывания. Для внедрения нужно согласовать DTO, типы, имена пакетов, правила валидации и транзакционную семантику с существующим кодом. REQ-FUNC-012 вне объёма. См. `../sdd/sdd-taskflow.md`, `../uml/static-traceability.md` и три исходника диаграмм. ADR-0001 остаётся действующим; в него следует добавить ссылку на данный ADR.
